## Specific causal question

At the same matched **actually selected** public feedback budget, did the opt-in original V22 fast local ring **change its learned parameters** but fail to change actions because V26's source/fast selector keeps reporting the protected source policy, or did the fast learner itself fail to convert novel reward credit into different action rankings? Both are plausible; measuring only V30's selected action regret cannot distinguish them.

The sole proposed manipulation is **evaluator-only frozen readout** from existing native V26 protected bank, exposing exactly three existing heads: unchanged SOURCE slow, trained FAST, and V26 ACTIVE selector. These readouts NEVER feed an alternative reward or policy into training. The associated **learning-disabled negative control** uses the same actually selected public action/reward events and original native API with `learning=False`, so no fast parameter update; it is labelled as a deliberately nonlearning reference, not an equal-update learning competitor. No original V22/V24/V25/V26 weights, features, gate thresholds or training loops are edited.

## Exact public event schedule (frozen)

First train original source V23 576 legal selected terminal rewards and obtain `selected_map()` twelve public (cue, actual-first, selected-second) histories, exactly as V29 and V30. The evaluator-only reward laws are original A, B, B0; A=B0 for all 36 context×second cases, A/B agree for the 12 common selected public rewards and differ only for unselected actions. All model arms are cold instantiated from the same source.

For each of A, B, B0 and budgets `0,1,3` independent replicate with **only** V30's frozen `novelty` external public chooser, exact previous context indices `(0,4,8)`. The first twelve legal events update fast V22 through V26, and the extra event action is selected by `PublicProbePolicyDev.select` on live V26 ACTIVE predictions before any B/A law lookup. Capture before and after each extra event: source-bank parameters SHA, fast-bank parameters SHA, V26 ACTIVE selector bit and last four public advantage measurements, native fast update count, 163 native fast learned parameters (digest only; never export or copy weights into another model), local reverse-credit neighbor message count, chosen action, selected public reward, selected-action pre-update prediction error and canonical checkpoint integrity. No regime label enters chooser or model.

For a strictly paired no-learning negative control, restore the same full checkpoint **after the 12 base events** and replay exactly the extra actions and actual rewards already selected by NOVELTY in its live arm using `learning=False`. Both arms observe the same public cue/actual first/selected second and evaluator-visible reward, but the negative control does not learn. The policy-selected actions are supplied as an external fixed schedule, not chosen independently by that control. If no-learning fast parameter SHA changes, engineering BLOCKED.

At budget 0, after each added probe at budgets 1 and 3, clone the full native model, freeze the clone via original `start_frozen_evaluation()`, and measure on all twelve public cue×first contexts and all three candidate second actions for each of SOURCE, FAST, ACTIVE; action is argmax by original ACTIONS ordering. Counterfactual rewards exist **only** in the evaluator regret calculation, after all action scores are fixed. Report all 12-context per-world total regret, 12-context action divergence from budget0, FAST-to-ACTIVE divergence, selected-action score margins, fast weights SHA difference, state selector switches, message resources and checkpoint bytes. Do not force `fast=True` on the live learner, silently promote source bank, overwrite bank fast weights, or choose a candidate because an offline outcome looks good.

**Same-selected-feedback conventional reference:** for A/B/B0 update the original full matrix online 80-feature RLS/CUSUM with the exact same 12+budget public selected events and actions as V30 NOVELTY; freeze and compute offline 12-context conventional action regret. This avoids mixing "choice improvement" with different actions and isolates whether the native local update captures the informative selected reward as usefully as a conventional model.
