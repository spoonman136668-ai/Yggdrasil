## Frozen hypothesis / bounded mechanism

Test whether the same already-public 24-event V31I development replay can reuse **one current public (cue, first) feature context** and at most **three identical scalar-mix vectors**, **only within the current accepted public first-action episode**, to retain nontrivial CPU savings while meeting the original V31M memory limit. No time-dependent retuning, extra task law, new holdout, source training, new action selector, model state or persistence. Restore the original module and class methods in `finally`. Make results copies on hits so the model cannot mutate saved state. Invalid inputs are always delegated to the original function for source validation. Clear both caches *after every successful* `SharedContextRingDev.accept_first` on the two native V22 banks, even when consecutive episodes repeat the identical public inputs. Never share cache across episodes, replay calls, cold restarts, separate trials, or systems. Maximum feature entries **1**; scalar mix entries **3** with deterministic eviction. Publish reset counts and peak keys. Calling wrappers is **external engineering** only; never alter the original source file, distributed cellular topology, learned weights, selector, stored counters or checkpoint format.
