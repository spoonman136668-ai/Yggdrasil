## Causal hypothesis and exact candidate design

The original native reward-output sites (0,2,5) receive only their own and two immediate neighbor binary feature bits per predictor call. Therefore a one-phase, binary neighbor-only observation/action representation has **at most four distinct local neighbor patterns per reward site**. Source-frozen one-phase 15-context encoding improved initial reward but failed unfamiliar transfer ([run #40589942586](https://github.com/spoonman136668-ai/Yggdrasil/actions/runs/40589942586)). The original action-input bit sharing reward-output sites caused an additional learned decoder shortcut ([run #40588085228](https://github.com/spoonman136668-ai/Yggdrasil/actions/runs/40588085228)).

**Candidate** uses two public-only, fixed, time-multiplexed *binary phases* on the five observation input sites (1,3,4,6,7). Each observation×action pair has a unique integer `t = action_index*5 + observation_index` in 0..14; define low `l=t%4` and high `h=t//4`. Per native input site, assign fixed 2-bit symbols: site1=h, site7=l, site3=l, site4=h, site6=l. Phase 0 transmits symbol bit 0 and phase 1 bit 1. Reward sites **0,2,5 always receive zero input bits**, preventing direct identity input/output overlap. Thus each original reward output cell can see a **4-bit two-phase local neighborhood word** uniquely distinguishing **all 15** public observation×action contexts at that cell (at most 16 theoretical possibilities). The encoding is deterministic and never consults evaluator reward law. A single phase still has max four local patterns; claims of full identifiability require both phases considered together.

The original `LocalTaskRuntime` 8-cell native genomics, neighbor graph, local memory, 17 memory learnable coefficients and public `public_outcome()` categories remain unchanged. The native predictor scores each candidate action from **two** predictions (average original reward-site readouts across two phases): six native calls instead of original three per decision. **Training uses one phase per genuine accepted public transition**, alternating `phase = transitions % 2`, with exactly one native `observe` and one actual public consequence per step; unchanged original native `core.events` count, learning rate, and safety. Both phases are therefore learned across successive transitions, not magically from the same single outcome; no extra reward information is provided, and phase was not a global hidden-state source. A sequence of two separate local predictions is added; the original native `LocalTaskRuntime.predict` is memoryless, so unique combined two-phase words do **not** prove the learned decoder can represent interactions across phases. A failure is a valid result.

The native input ABI changes: bump bridge checkpoint schema v2→**v3** and fail closed on v2 historical checkpoint restoration. Transition counter determines current training phase, is sealed and restored, and must be verified across fresh interpreter boundaries. Do not rewrite existing owner checkpoints.

## Locked independent on-policy test

Use wholly fresh evaluator-private synthetic task families **70..77** × seeds **68..75**, eight each, 64 matched trials, 90 initial familiar-context + 90 unfamiliar/changed-reward contexts, three public reward classes **−3,0,+10**. Four fully acting independently trained public-only actors per source checkout: native model, full-history selected-action mean, EMA 0.5, rolling reward window six. Same deterministic source-blind action probe opportunities and public observation clock; actual chosen action determines its reward. **46,080 public action-feedback events per implementation per OS**, Linux and Windows, pinned original PR #582 v2 vs two-phase candidate v3. Fresh Python interpreter restores both native/memory states at the 90-event boundary. Record mean actual reward initial and unfamiliar, last-24 reward, frozen heldout, raw trial wins/ties/losses, native predictor inference-call and message overhead, CPU/RSS, checkpoints, source SHA, and full conventional controls. Follow exact original native non-Atlas regressions, plus custom two-phase codebook uniqueness/locality/parity and historical checkpoint denial tests. Note hosted-runner CPU is not proof of retail workstation parity.

**Precommitted acceptance veto:** If candidate does not beat original native in **both** phase mean rewards with fair feedback budgets, if it still materially trails independently acting conventional recency baselines, or if custody/regression/resource gates fail, it cannot be promoted. Even a development positive must later pass exact-source G29 Atlas, genuine source-owner FSA, retail Windows resource acceptance, source-owner crash recovery, and external-family transfer. No repeated coefficient/codebook tuning on this holdout. All draft and active research unaffected.
