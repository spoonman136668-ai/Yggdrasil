# ITD-02 V31S: independently executing eight-process ring transport, prospective protocol

**FIRST committed file**, before evaluator/workflow. Frozen exact V31R draft PR #644 head `5ac34b12739d06ef7b50786bacf7bca893374407`. V31R is positive **only for external bank-local Python slot emulation**. V31S asks a harder question: can eight distinct OS processes own individual cell state, exchange actual messages ONLY with their two original ring neighbors, return the unchanged public feature rows, and preserve original learned-model behavior? We expect high IPC and process overhead; no optimizing away accounting and no claim that Python child processes are native Yggdrasil cells.

## Fixed architectural intervention

Eight distinct Python `multiprocessing.get_context("spawn").Process` children, **one per original cell ID 0..7**, run actual separate OS processes (distinct observed PIDs). Each child receives only its **own seven-channel site-local public pulse**, its own bank ID/episode identity, and two direct duplex `multiprocessing.Pipe` neighbor endpoints. Edges are exactly `(cell-1)%8` and `(cell+1)%8`; NO direct links to non-neighbor children; no shared memory, module-global memo table, manager or global tensor visible inside child. Parent must never pass any neighbor state or assembled 8-cell matrix to children. Input fanout and final feature-row gathering by parent are **explicit orchestration**, not autonomous cells.

Each fresh public bank/episode: first request performs **four synchronous neighbor-only exchanges** of the original V18 fixed `INITIAL_GAIN=.92`, with each child sending its OWN current vector along each directed neighbor edge before reading both neighbors' previous-hop vectors; update each channel via **unchanged original `min(2., max(own, gain * max(left,right)))` rule**. Each neighbor packet is UTF-8 canonical JSON bytes with explicit `episode,hop,source,7-element state`, independently validated on receipt. Each child constructs its **own** original 20-element feature row `[1] + seven delivered signals + 12 cue/action products` and retains one immutable row per bank ID, invalidated ONLY after original `SharedContextRingDev.accept_first` succeeds. Subsequent reads come from the owning child's row; no parent memo of the 8 returned rows. Original `SharedContextRingDev._features` + `accept_first` may be temporarily redirected **only inside the external evaluator**; the original `_site_features`, `_mix_scalars`, scoring, reward updates, model checkpoint and source-training modules stay byte-exact and are not patched. All patches restored via `finally`. Workers are joined/terminated with bounded timeouts; no service, daemon or persistent deployment.

Input and output transport is actual OS Pipe IPC. Count and verify **number and UTF-8 payload bytes of messages sent and received** separately for neighbor edges and orchestrator fanout/gather. Expected exactly `48*8*2*4=3072` directed original-neighbor messages for a full original V31I 24-event replay across two banks; each worker owns exactly one cell (max two independent live bank rows), no wrong-hop/duplicate/out-of-order neighbor packets, all sent=received counts and bytes, and each worker PID distinct from parent and other workers. These are measured **serialized IPC bytes**, *not physical NIC bytes, wire/energy metrics or a smaller number of native original message units*. The original V22 virtual scalar-hop counters and original checkpoint must not be rewritten to match actual JSON IPC bytes.
