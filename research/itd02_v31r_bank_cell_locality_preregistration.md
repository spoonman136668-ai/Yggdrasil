## Prespecified mechanism, three arms

* A: original `DistinctReturnRingDev` and original `SharedContextRingDev._features`, no cache.
* B: **V31R bank-local cell-slot emulation**: temporarily adapt only `SharedContextRingDev._features` and `accept_first` in the evaluator process; assign exactly **8 independently keyed one-entry cell representation slots PER live bank object**, never a global cue-key lookup, global `OrderedDict`, or cross-bank slots. Each cell slot owns its own immutable 20-dimensional representation row for the currently accepted public `(cue,first)`. On the first feature request after validated `accept_first`, the original pure `_features` executes original source pulse transport/validation **once** to populate all eight cell slots; subsequent `_features` calls may only copy back their eight individually owned local rows. Clear each cell slot after original `accept_first` succeeds (no clearing on rejected input); never share slot state across different banks, different public episodes, process workers, or cold restore. The original model's `score`, `accept_second`, `_coefficients`, `_mix_scalars`, reward-credit and output scalar routing all execute originally **without any cache**. V31N's global module `_site_features`/ `_mix_scalars` wrappers are NEVER installed for arm B. Guarantee patches restored in `finally`; slots are ephemeral Python attributes not serializable checkpoint state. Strictly record max 8 slots/bank, original feature builds/hits/invalidation counts, original output mix untouched. The adapter is run **only externally** in `research/`, not shipped in `yggdrasil/`.
* C: unchanged frozen V31N central cache comparator (1 feature key + 3 scalar-mix keys, reset after accepted first) on the exact same source and events, with frozen original module restored afterward. C is for efficiency comparison, NOT a native competitor or scientific baseline.

**Critical interpretation:** Although slot ownership models per-cell responsibility and no global memo mapping exists in B, the prototype still calls original `_site_features` once per bank/episode and centrally assembles returned rows from one Python bank object. This does NOT prove truly independently scheduled eight-cell execution, genuine native locality or fewer physical communication bytes. Native-cell design/promotion cannot be inferred even if process CPU improves.
