## Mechanism of potential benchmark leakage

KNOW14's generator sets the true cue **uniform 0 for all A entities** and **uniform 1 for all B entities**, but makes each distractor cue balanced within both tasks. This creates a unique **source-statistical signature** visible directly in the Q/P/Q facts before any intervention. Merely not passing the task-phase bit to native input does not remove this easy factual-only shortcut; the research driver still knows which source cohort is A and which is B.

The source-only baseline reads each of four `P961..P964` candidate cue values from NKR08 for only 32 FIT entities in each task. Each bit requires exactly one of two source-typed witnessed `Q/P/Q` memberships. Select a cue only when it is constant within both cohorts and has different values between them. No other inference or learned mechanism. The selector returns **ABSTAIN** if any source fact is missing, contradictory, forged or if 0 or 2+ cues qualify. The hidden generator role is inspected only after the selector returns.

**Frozen budget:** 256 candidate source values/seed ×3 = 768 source values, 1,536 Q/P/Q membership probes, **zero witnessed actions**, no new protected original-world data. Compare selected roles with KNOW14 receipt from the *same source-run* (384 witnessed actions) rather than changing KNOW14's threshold or rerunning a new source.

**Falsification criterion:** factual-only must identify exactly **3/3** same roles with **zero** action consequences. If it does, mark `KNOW14_CUE_IDENTIFICATION_CAUSAL_WITNESSES_NOT_NECESSARY`: the observed cue-identification evidence does *not* show that interventions were necessary to find the cue. This does not falsify KNOW14's valid synthetic same-slot retention, factual-to-action fitting or policy predictions, which still used witnessed outcomes.
