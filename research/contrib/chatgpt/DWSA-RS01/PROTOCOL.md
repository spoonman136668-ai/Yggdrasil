## Source-free interface and frozen development rule
See [identity_gate.mjs](identity_gate.mjs) and [focused fixture tests](identity_gate.test.mjs). The utility itself **does not load donor weights or data, invoke a teacher, execute environments, train native Yggdrasil, or perform model checkpoint writes**. It takes externally supplied probabilities from already-authorized frozen predictors:
- `raw` = frozen raw-identity recipient prediction, `donor` = independent frozen donor-feature recipient prediction, both probabilities in [0,1].
- `key` = audited, pre-action, public-context bucket; `id` = unique source witness identity. Labels `y` appear only in designated FIT and VALID rows, not in prediction-time observations.
- Required disjoint partitions: `FIT`, `VALID_OLD`, `VALID_NOVEL`. Duplicate row IDs, out-of-range probabilities, malformed keys, wrong splits and invalid binary labels fail closed. A future source owner must independently enforce source identity, time-consistent observations and cohort separation: caller-supplied `split` strings are **not proof** of custody.
- Up to **16** correction cells, ordered by descending FIT row support then lexical key; each shift is `clip(sum(FIT_y - FIT_raw)/(count+20),-0.1,+0.1)`. No donor or validation labels are used to fit corrections. Unknown keys have shift **zero**. No adaptive repetition or post-result parameter search.
- Candidate probability is `clip(raw + capsule[key] + gamma*(donor-raw),0,1)`; gamma candidates `[1,0.5,0.25]`. For each gamma, require **VALID_OLD** Brier drift vs raw no greater than `+0.02`, **VALID_NOVEL** improvement vs raw at least `0.005`, and donor incremental gain vs *raw plus the same fitted capsule* at least `0.002`. Choose the lowest novel-validation Brier among passing candidates, tie-breaking toward smaller gamma.
- **Atomic reject**: if none passes, return gamma **zero** and an **EMPTY active capsule bank**. Keep proposed capsules only for developer diagnostics, never attach them to the accepted predictor after rejection. Unseen context with no active correction reduces exactly to the unchanged raw probability. Independent previous native state remains untouched.
- This utility has no authenticated checkpoint envelope or independent novelty verifier; those remain obligatory before native use. `VALIDATION_ADMITTED` means **only this development rule passed its own validation data**, never scientific promotion, benchmark acceptance or owner approval.

## Post-design engineering correction — scope and minority-retention regressions (2026-11-21)

This section was appended **after** the original source-free RS01 development rule and its fixtures. It is an engineering defect correction, **not** a preregistered new scientific experiment. The original text above and [initial code commit](https://github.com/spoonman136668-ai/Yggdrasil/commit/8272b3212d715e4bfaafcb9794810b62b1da1bbf) remain as historical evidence. Neither fixture's labels or outcomes authorize tuning or reuse of protected source evidence.

### Reproduced original failure cases
1. **Unseen-key donor overreach** — original module at blob `0f7a0e1788ad34126761a704df08968b32151ef5`: accepted `gamma=1` using FIT/VALID contexts `A/OLD/NEW`, then on never-seen context `UNSEEN_CAUSAL_CONTEXT` with raw `0.95`, donor `0.05`, returned **0.05**, not raw 0.95. Hypothetical true label 1 gives squared error **0.9025 vs raw 0.0025**. Prior `identity_fallback` test exercised only `gamma=0` and missed the failure. This is a **source-free adversarial counterexample**, not observed source-world forgetting.
2. **Minority old-context regression hidden by mean** — after first scope fix, 99 old observations in `COMMON` and one in `RARE` yielded aggregate old-validation Brier drift **+0.009** (inside +0.02 limit) but the `RARE` prediction changed 0.95 to 0.05, a **+0.900** per-context squared-error degradation. The donor was wrongly admitted. The observation was in the original `VALID_OLD` input, so the error was a defective aggregated gate, **not** unfamiliar-cohort generalization.

### Corrected DEV-only mechanism
- Donor influence is **only applied to exact public-context keys present in the supplied VALID_OLD or VALID_NOVEL partitions**, stored as a sorted unique `donorKeys` allowlist capped at 16 keys. Any key outside that observed context set suppresses **donor gamma contribution**. The FIT-derived correction remains independently bounded and available only on its FIT-supported correction keys; an unknown key has neither donor contribution nor correction and falls back exactly to raw.
- Reject malformed/duplicate/oversized allowlists and >16 validation keys. This limits development-state memory but does **not** prove the source witness identity, future novelty, or that an authenticated owner authorized a key. User-supplied validation context keys are a proposal, not a trust anchor.
- Require **both** overall VALID_OLD Brier drift <= +0.02 **and each observed old-key group's Brier drift <= +0.02** before admitting any donor gamma. Positive donor increments and VALID_NOVEL requirements stay unchanged.
- If rejected, active gamma=0, active donor allowlist empty, active repair cells empty. Proposed capsules remain diagnostic only. Original trained raw predictor is unchanged.
- These changes narrow donor activation to validated key identities; **they do not establish robust unseen-causal-family transfer**, and a new law/context ID may intentionally trigger conservative raw fallback instead of donor transfer. Per-key validation can still miss within-key failures, small-sample variance and unobserved distribution shifts; do not claim protection beyond the tested fixtures.
