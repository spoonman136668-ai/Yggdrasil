WHY THIS CONTROL EXISTS
-----------------------
The independently developed exact untruncated Bayesian run-length model
(bocpd_exact_reference.py.txt, PR head 061d7de62b) is sound as a conventional
out-of-budget predictive reference, but its fully fitted 192-step checkpoint
requires 13,428 bytes. RF32 is likewise out-of-budget. To complete a
meaningful in-budget comparison, this gate builds a distinct 896-byte
persistent-state BOCPD with 14 action-context bins, 16 isolated addresses,
fixed hazard 1/32 and Beta(1,1) public-only Bernoulli emissions.

SERIALIZED BUDGET AND LIMITATIONS
---------------------------------
For 16 addresses (7 active plus 9 retained):
- actual prior-two-action history: 32 bytes
- per-address last-32 event records in packed 5-bit 14-bin format: 320 bytes
- occupied ring lengths and write heads: 16 + 16 bytes
- 32 fixed-point posterior weights per address (Q8, sum 255): 512 bytes
TOTAL PERSISTENT LEARNED/HISTORY STATE: 896 bytes (<928).
Checkpoint magic 4 + state 896 + SHA256 32 = 932 bytes.
The 932-byte serialized checkpoint is NOT the 896-byte learned-state budget.
Python heap and transient posterior calculations are additional runtime costs,
not hidden persistent model state. In-process memory and full-process resource
parity against native Yggdrasil have not been measured.

The generative prior assigns per-observation change hazard H=1/32 and
predicts H*0.5+(1-H)*sum_r P(r)*p(y=1|recent r public observations).
Per-bin Beta(1,1) conditional emission probabilities are fully fitted on
past public counts. The run-length posterior is not fully exact: Q8
quantization, a bounded 32-public-event tape, and a folded r>=31 tail are
explicit approximations. Do NOT call it an exact or untruncated BOCPD.
Its distinct LRB1 snapshot does not migrate/change original PYC1/YPT3 or
other native formats. Hazard, precision and window were fixed prior to this
gate's fixture scoring; no hyperparameter sweep or post-primary retuning.

DEVELOPMENT INTERPRETATION / STOP RULE
--------------------------------------
The 896-byte bounded Bayesian model beats the original YPT4 candidate
on BOTH B and early A-return on these TWO disclosed development fixtures.
It does not beat hard MAP HMM on early A-return in either, nor does it
demonstrate universally strong cold recovery. This is negative evidence
against the current YPT4 candidate's proposed mechanism, not a statistical
primary result. Returning A is observationally indistinguishable from
continuing B before new public evidence absent a cue; do not award oracle
first-step return identification. None of these data supports science
promotion, general intelligence or native cumulative learning.
