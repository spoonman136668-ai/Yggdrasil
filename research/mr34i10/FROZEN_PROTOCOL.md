## Hypothesis

Replacing Decimal48's costly arbitrary-precision exponential with deterministic Python-integer Q160 range-reduced Taylor arithmetic can preserve bit-exact cross-OS/native-source trained checkpoints and identical binary64 sigmoid quality with materially less CPU. One unconstrained **source-free** local pre-protocol diagnostic on 1,009 deterministically generated and edge floats agreed with Decimal80 to exact float bytes and indicated faster computation; those are **not** scientific original-source observations and do not constitute qualification.

## Frozen source-neutral alternative

For each finite binary64 `x`, clamp to exact original [-35,+35] as `x=max(-35.,min(35.,float(x)))`, `S=1<<160`, `(num,den)=abs(x).as_integer_ratio()`, `q=((num*S)//den)//128`. Initialize `value=S`, `term=S`. For k in **1..59**, set `term=-(term*q)//(S*k)`, stop if term==0, otherwise `value+=term`. Square/reduce **seven** consecutive times `value=(value*value)//S` (approximates exp(-abs(x)) from exp(-abs(x)/128) by repeated dyadic squaring). Return standard IEEE binary64 conversion `float((S if x>=0 else value)/(S+value))`. This algorithm must be identical across both original OS implementations. Zero extra trainable parameters. Check finite output in [0,1] and monotonic on original boundary/neighbor input ordering. No NumPy exp, math.exp, Decimal or source-specific lookup inside **candidate** inference.
