## Scientific challenge and constraints

Unlike CS06's explicit 13-category cumulative count, original `ConcentrationHard()` requires learning a transient **card-position -> observed rank** association through *chosen* public flips, remembering earlier positions while cards return face down, and recalling a partner when available. No perfect matching target, original shuffled deck, hidden `get_state`, original `deck`, face-up private indices, source rank lookup, or privileged info may enter model code. Source `reset/step` only; public observed 52-value board with original facedown sentinel 13, previous *own* chosen position and original scalar reward are allowed. Candidate and controls share deterministic public action rules and information at each action, subject only to explicitly bounded **unmatched revealed position-to-rank memory** capacity. All arms may track the already-matched positions revealed in CURRENT public observation, their own last action, whether a pair is halfway through, and public action count; these are common, so the K=0 arm is *not strictly memoryless*. Important: do not pretend it is a true no-state policy or that the agent autonomously learns card identity/perception.

## Predeclared algorithms and strongest competitor

A COMMON navigation/exploration policy is deterministic, never sees source-private state:
- At start of each pair, if stored *unmatched* locations contain two face-down cards with equal legally observed rank, choose one to attempt a match. Else choose a face-down position via a deterministic step-index-based traversal that prefers locations not in current stored memory when legal. Since this schedule is fixed and no rank evidence is available otherwise, it cannot use hidden original layout.
- After a first card flip, inspect the **actual public board** at the next source step for the revealed rank of the just-flipped card. If an unmatched stored location has the same rank, choose it; otherwise choose a legal other face-down card, preferring unremembered locations when possible. After second original flip, update associations strictly from the **public board** returned by source step and remove cards that legitimately matched (positive original reward); return to pair-start. Never flip the same index twice in a pair or a position that is currently known matched.
- Update the `K` unmatched position-rank cache online from *publicly revealed* original card ranks, as a FIFO of distinct unmatched positions. Capacity=0 stores no unmatched position->rank associations, capacity=52 stores all 52; 4/16 bounded. All policies may record own action and the public set of already permanently matched cards. The selected budget is FIT-trained via actual original-source rewards; the *memory architecture and FIFO eviction heuristic are hand-designed*, not autonomously discovered sufficient statistics. This is online card-association learning with prospective FIT-selected capacity, not learned feature extraction or a non-transformer novelty proof.
